## 照らしの決まり（`btruth check`）

- **範囲**：既定は承認済みの要素の全部。承認の後は、承認した要素と、つながりで一段先の要素（C-8）。
- **属性ごとに全部の出どころを並べる**（C-3）：出どころごとに最新の版の承認済みの観測を一つ。未決は入れない。
  - 人の判断（採用）が、格の高い書類の決定と違う → 「決定が未反映（人の判断と食い違う）」。選択肢は「議事録に合わせる」「判断を保つ」（例8）。判断の格は、根拠の書類を添えればその格、なければ設計図と同じ 5（決定 Q8）。
  - 一番格の高い書類の値が、主の出どころの値と違う → 「決定が未反映」。格の高いほうを「正とみなす」として示し、主の出どころの書類に修正案を出す。確定は人（例3）。
  - 従の出どころが主と違う → 「言い分の食い違い（主と従）」。主を基準に、従の修正案（例2）。
  - 施工図が設計図と違う → 「設計図と施工図の食い違い」。正を決めず、修正案も出さない（C-10）。
  - 同じ格の書類が食い違えば、書類の日付で新しいほう。日付がなければ「新旧が決まらない」。
  - 議事録の未決 → 「議事録の未決」（記録のみ。Q30）。
- **比べ方**（決定 14）：書類どうしは、ぴったり同じかで比べる。図面の形を測った値（DXF の出どころ）は、`same_position_mm`、幅は図面と書類のあいだで `door_width_tol_mm`。
- **型と実物**（決定 9）：同じ属性の観測が型と実物で違えば「言い分の食い違い（型と実物）」。注記などの層の例外の観測は、採用されるまで層に効かない（例5）。
- **区間**（C-2c、例11）：壁の区間は壁が直接接する所だけ（くり抜く開口の所は抜く）、開口の区間は開口の所。境界の種類は全長に一つの値か、区間ごとの値（Q20）。物理的な区間で相手のない所は「壁が途中で終わる」。向かい合う二つの境界で、同じ線の上の種類が違えば「向かい合う境界の種類の食い違い」（決定 6）。
- **壁と境界のずれ**（例1）：壁がずれた境界の相手の壁は、「壁が境界の外に出ている」「壁が途中で終わる」に分けて出さず、ずれ一件にまとめる（`expected_diff.md`）。
- **開いている要確認**（決定 15）：同じ範囲の新しい照らしが、前の照らしの要確認に置き換わる。保留中の要確認と、範囲の外の要確認は開いたまま。人が答えた要確認は、同じ言い分の組で二度出さない。
- **判断の前提の変化**（決定 Q27 の足し）：照らしのとき、判断の前提にしたルールの表の写しが新しくなっていれば、その判断に再確認の印（`caused_by_kind=table_load`）。頼った前提が却下されていれば `assumption`。

## 出どころの間の同定と、意味の面の変化

- `btruth identify-sources <物件> --interpretation <新しい出どころの解釈>`：新しい解釈の要素を、既にある要素と鍵（符号・室番号・名称）と足場（柱なら載る通り芯の符号）で照らす。同じなら、新しい出どころの言い分を既にある要素の言い分として足す item（承認待ち）にし、提案の要素は「同じ要素に統合」として承認の一覧から外す。一つに決まらなければ「同じ要素か判断できない」で人に渡す（B-13、例2）。
- 表の新しい版の同定：鍵（行の最初の値）が同じで中身が違う行は「意味が変わった」。その型を `型である`・`使う` で使う実物に付いた判断に、再確認の印（`caused_by_kind=source_version`）。有効値は採用のまま（決定 9）。
- 凡例の新しい版の同定：記号の定義の中身が変わると、その定義を凡例として指している要素も「意味が変わった」。

## 人が試す DB（`out/try5`）と、打つ順

テスト用の解釈（固定の解釈）は入れていない。入っている解釈は二つで、`items` の出力の名前で区別できる。下の ID は、報告の前に `items` の出力の名前と照らした。

| 名前（`items` の表示） | ID | 何か |
|---|---|---|
| `Claude Code` の解釈 | `ef8258fc` | 平面図（扉つき）・壁種表・仕上表・建具表・議事録を読んだ AI の読み（`samples/ai_run/step5_claude.json`） |
| 建具の型 AD-1 | `d026549a` | 建具表の行。幅 800 |
| 建具 AD-1 | `373e6b7a` | 図面の扉 |
| 開口 | `e9a30a3c` | 間仕切の開口。幅 800（図面） |

議事録には、決定「AD-1 の幅を 900 とする。」と、未決「WT-3 の外壁の断熱は次回までに検討する。」がある。

リポジトリのフォルダで PowerShell を開き（Claude Code の中ではない）、この順で打つ。確定のコマンドは、一覧を出してから「確定しますか？ (y/N)」と聞く。

```
.venv\Scripts\python -m btruth items out\try5
.venv\Scripts\python -m btruth show out\try5
.venv\Scripts\python -m btruth approve out\try5 --interpretation ef8258fc --reason "図面と表と議事録を見比べた"
.venv\Scripts\python -m btruth issues out\try5
.venv\Scripts\python -m btruth choose out\try5 --issue <「決定が未反映」の要確認の ID> --option <選ぶ code> --reason "…"
.venv\Scripts\python -m btruth values out\try5 --element d026549a
.venv\Scripts\python -m btruth values out\try5 --element e9a30a3c
.venv\Scripts\python -m btruth issues out\try5
```

- `approve` の後に照らしが走り、`issues` に三件が出る：「決定が未反映」（AD-1 の幅。議事録 900 と建具表 800）、「議事録の未決」（記録のみ）、「名前がない空間」（左の部屋）。
- 「決定が未反映」の要確認の ID は、`issues` の出力の「要確認 …」の行から写す（承認の後にできるので、ここには書けない）。選択肢の code は［ ］の中：
  - `type_width`：型（AD-1 全体）の呼び幅を 900 に（建具表の修正案）
  - `door_width`：この建具だけの呼び幅を 900 に
  - `opening_width`：この開口の幅を 900 に（穴・境界の区間・数量が同じ値を使う）
  - `keep_lower`：却下（建具表のまま。理由を書く）
- 修正案は、`issues` の「修正案:」の行に出る（建具表 の AD-1 の 幅 を 900 に直す）。
- `values` は、属性ごとの有効値と、その出どころ、全部の言い分（観測・採用、決定・未決）を出す。座標は通り芯の符号の交点に揃えて出す。たとえば `opening_width` を選ぶと、開口の幅が 900［採用］、建具の型の幅は 800［承認済みの観測］のままで、議事録の 900 は「観測 決定」として並ぶ。
- 試し直すときは `out\try5` を消し、`init` → `import` 五つ（`docs/STEP5.md` の上の表の出どころ。議事録は `--kind 議事録 --document-date 2026-10-15`）→ `propose samples\ai_run\step5_claude.json` で作り直す。ID は変わる。

## 設計書と違う作り方をした所

- **Q29**：主の分野は保存せず、読むたびに主の表から求める。
- **Q30**：議事録の未決は、要確認「議事録の未決」（記録のみ）として残す。
- 開いている要確認の読み方（決定 15）に、「人が答えた要確認は、同じ言い分の組では照らしが二度出さない」を足した。照らしを何度走らせても、答えた判断が要確認に戻らないため。
- 壁と境界のずれのある壁と境界には、区間の要確認を出さず、ずれ一件にまとめた（`expected_diff.md` の「バラバラには出さない」）。

## 第5段で作っていないもの・限り

- 例4 の「壁種の層の組み立てに断熱材の層があるか」の照らし（主＝壁種表、従＝図面の記号）は、まだない。凡例の要素を根拠にした読みと、凡例の変化の伝わり方だけを作った。
- 柱の位置の食い違いは、図面どうしの幅 `same_position_mm` で比べる。偏心の上限（`column_offset_max_mm`）で「普通の偏心」として要確認にしない（D-8）扱いは、まだない。
- 出どころの間の同定の鍵は、符号・室番号・名称と、柱の載る通り芯。部屋の室番号での同定はテストしていない。
- 照らしの後の `check_run.counts_json` は空のまま（行は書き換えない）。数は `run_summary`（整合の照らし）に残す。
